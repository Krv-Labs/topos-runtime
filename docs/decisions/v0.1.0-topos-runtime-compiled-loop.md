# Decision Record: Topos-Runtime v0.1.0 Closed-Loop Compiled Binary Optimization

**Status**: Approved & Landed  
**Date**: 2026-08-20  

## Context & Motivation

Source-level Topos evaluates AST, CFG, CPG, and MDG structures across four quality pillars (`SIMPLE`, `COMPOSABLE`, `SECURE`, `NAVIGABLE`). However, source quality alone does not capture binary compilation efficiency, profile-guided execution hot paths, instruction layout, hardware counter performance, or energy consumption.

**Topos-runtime v0.1.0** introduces a closed-loop compilation and binary evaluation agent that extends category-theoretic evaluation to compiled binaries and intermediate representations (LLVM bitcode `linked.bc`, MLIR payload IR).

## Architectural Design

### 1. Compiled Subobject Classifier ($\Omega_{\text{bitcode}}$)
The compiled Heyting algebra subobject classifier is formed by four pairwise incomparable generators:
- **`SPEED`**: Wall-clock performance, profile-guided hot path edge counts, and branch/call execution frequency.
- **`SIZE`**: IR and binary instruction counts, layout density, and section sizes.
- **`ENERGY`**: RAPL microjoules energy consumption, IPC, and cache/branch miss hardware counter rates.
- **`LOCALITY`**: PDG/CFG critical paths, loop vectorization status, and MLIR fusion/tiling graph quality.

Medal tiers are derived directly from the satisfied generator count:
- **PLATINUM**: 4 satisfied generators.
- **GOLD**: 3 satisfied generators.
- **SILVER**: 2 satisfied generators.
- **BRONZE**: 1 satisfied generator.
- **SLOP**: 0 satisfied generators.

### 2. 5-Phase Closed Optimization Loop

```
Evaluate Baseline → Identify Bottlenecks → Propose Optimization Plan → [Human Gate] → Recompile & Verify Gains
```

1. **Phase 1 (Baseline Evaluation)**: Runs benchmark workloads, collecting wall-clock timing, instruction counts, and `perf`/RAPL hardware counter statistics.
2. **Phase 2 (Opportunity Identification)**: Analyzes `linked.bc` and `.profdata` to highlight hot functions, vectorizable loops, branch misprediction hotspots, and MLIR fusion gaps.
3. **Phase 3 (Optimization Plan)**: Constructs an explicit `OptimizationPlan` detailing pass sequences, PGO flags, target thresholds, and strict risk/regression bounds.
4. **Phase 4 (Human Approval Gate & Recompilation)**: Recompilation executes **only** after explicit sign-off. Applies passes (`opt`), PGO profile flags, or MLIR lowering scripts to build a candidate binary.
5. **Phase 5 (Verification & Rollback)**: Measures candidate binary performance against baseline metrics. If empirical gains satisfy plan bounds, the compiled medal is updated; otherwise, the binary is rolled back via `ArtifactStore`.

- **CLI Subcommands**: `topos compiled evaluate`, `inspect`, `plan`, `recompile`, `compare`, `rollback`.
- **MCP Tools**: `topos_compiled_evaluate`, `topos_compiled_identify_opportunities`, `topos_compiled_propose_plan`, `topos_compiled_recompile`, `topos_compiled_verify_gains`, `topos_compiled_rollback`.
